# v7.2 人物自动规划方案

由输入图像提取开放走势，在共享画布上生成真实笔迹。v6 人工指定 20 条走势的完整实现保存在 `archive/v6`；v7 不为验收图手写坐标或笔序。当前是人物生成实验，不是人体理解模型。

## 输入到画谱

| 环节 | 当前实现 | 边界 |
| --- | --- | --- |
| 预处理 | EXIF 方向、白底合成透明图、等比例归一分辨率 | `sourceSize` 记录工作分辨率 |
| 开放走势 | 低频 Lab 色面、连通支持场、PCA／平滑骨架主轴、局部笔宽 | 支持场只供分析，不裁切绘画 |
| 访问顺序 | 大视觉质量与邻近端点共同排序，可反转方向 | 不理解人体部位或遮挡 |
| 底形与大明暗 | 直接沿轴塑形、读取主面与转折残差（已删除网格铺色前奏） | 剖面代理不等于人能认出形体 |
| 体积与细节 | 方向场、结构张量与画布残差 | 粗层预算阻塞时不进入后续精修 |
| 时间轴 | 串行笔迹、起止时间与抬笔间隔 | 对数播放只改展示时间 |

`auto_guides.py` 提取走势；`build_portrait.py` 调度阶段；`construction_episodes.py` 提出、预演和评估笔触；`global_plan.py` 组织注意路线与时间轴。Haar 正脸检测仅提供可选注意焦点，不产生姿态、衣物或前后遮挡信息。

## 未完成反馈与停止

v7.0 的补画重新执行有限 episode 后仍可离开未完成走势。v7.1 将实际 `needsRevisit` 报告传入同一走势的补画，并重新读取当前画布：主面不连续时优先宽载色，主面已成立而对比对应不足时选择转折侧向；保留开放轴上的局部与整段候选，不产生封闭人体块。

初始笔和补画候选均先在画布副本上预演。只有粗层剖面 MAE 不增、就绪站点比例／最长连续比例／对比对应不退，并达到最小收益时，才完整落下该笔。评估不选择性擦除笔迹内像素，绘画仍允许自由重叠纠形。

补画最多 5 笔，不能无限重试。终止决策分别记录：

| 决策 | 含义与后续 |
| --- | --- |
| `proxy_ready` | 达到剖面代理，允许转移；不是语义或人工验收 |
| `stalled_unresolved` | 当前开放轴上没有安全粗层改善，明确保留未完成状态后允许转移 |
| `blocked_unresolved` | 补画预算耗尽且未就绪，停止当前阶段余下走势、精修和后续阶段 |

阻塞信息导出为 `constructionBlocked`，当前层为 `layers[].complete=false`。`complete=true` 只表示调度结束，可能包含明确记录的停滞走势。CLI 和批量入口遇到预算阻塞返回 1；批量结果为 `incomplete`，仍保留 HTML、SVG、画谱及耗时。这样可以检查失败，不把未完成画面包装成完整四阶段结果。

这一闭环限制了错误继续扩散，尚不能自动修正所有错误开放轴。走势是否穿过错误形体、宽度或方向是否合适、停止是否过严，应结合固定样例的早期过程判断；是否加入人物开放结构提示仍由失败证据决定。本次不引入姿态模型或逐图人工修正。

## 渲染、版本与对照

每笔保存中心路径、左右边界、颜色、透明度和时序。当前生长几何只截取已经走过的路径及边界；已完成笔触通过 Canvas2D `Path2D` 缓存相同 SVG 路径，当前一笔为 SVG。导出以画谱为依据，不以截图、视频或原图显露替代矢量。

`tools/render_player.py` 与 `pack_v7.py` 打包当前版本的播放器及完整生成代码，拒绝旧版画谱与当前源码误配；历史 HTML 保留。`tools/export_svg.py` 导出静态矢量帧，完整动画仍由 HTML 播放。对数映射为 `t=T·ln(1+99s/D)/ln(100)`，反函数推进原始时间，笔序与几何保持不变。

`tools/gallery_baseline.py` 复用固定输入 SHA256 清单、保留选样依据、源码哈希、参数与耗时。`tools/compare_baseline.py` 要求两版输入顺序、SHA256 和参数相同，导出第 100／140／185／210 笔及转移附近 SVG 静帧，并提供相同原始时间、连续 1× 的真实 SVG 回放片段。笔数或共同时间不足明确标为不可用；阻塞末尾不伪造下一次转移。

## 验收边界

家庭机已固定 5 张真实图库人物插画，原版基线位于本地 `generated/gallery-v7.0/manifest-v7.0.json`，统一 640 最长边、前两阶段。样例覆盖头像、半身、坐姿全身复杂服饰、双人和动态人物，不覆盖照片人物或中性站姿全身。

程序代理、人工观看和最终相似度分别报告。`readableProxy` 和最终 MAE 均不能证明人物可辨或绘画自然；模拟 DOM 测试也不能证明浏览器帧率。完整执行结果以当前交付状态和本地清单为准，源图库和大生成物不入 Git。v7.2 当轮未部署 Pages；2026-10-27 已依用户明确授权启用 Actions 发布机制，选定 HTML 的参考预览与画谱在本轮公开范围内，首轮部署仍待完成。

## v6效果基线与已确认退化

用户已要求以v6为基线。原参考图按1086×1448原生尺寸比较，20条人工轴及真实访问顺序只用于评估，不输入自动生成器。v7.2仍不能模拟最初腿部走势；删除网格前奏只是必要修复，未解决合并场PCA过宽和长腿缺失。打包模板与作品入口分开，严格填充指定script容器；历史选定HTML保留在artifacts/v7.2，最新完整实验回放在artifacts/v8.1，历史引擎/画谱/播放器版本分别注明，原图库不整库上传。

## 完整 HTML 与静态发布

`tools/publish_experiment_artifacts.py` 只打包显式指定、SHA256冻结的64笔画谱和已有对照，不重跑绘画。源码从固定 Git 提交读取真实模块依赖闭包，ZIP 中记录逐文件哈希；HTML 内嵌相同完整 ZIP，画谱公开副本仅脱敏本地路径，保留所有笔触值。原图和显式输入契约仍需调用方提供，不能由参考预览反推。播放器/数据模式7.2与生成实验 `portrait-coarse-v8.1` 分别标注。

`tools/build_pages_site.py` 使用标准库构建全新输出目录；只接受v8.1/v7.2 manifest白名单并生成导航门户，拒绝坏路径、坏链接、软硬链接、缺失或未列明文件、哈希不符和超限体积。它复用 `validate_publication` 检查v8.1内嵌ZIP、外部ZIP和公开JSON的一致性，因此仅重新计算外层manifest不能掩盖语义篡改。`.github/workflows/pages.yml` 在PR上只校验，main push/手动运行时才上传独立站点并部署；Pages/OIDC写权限仅在部署job，`github-pages`环境与main提交核对控制发布来源。运行步骤见 [Pages 发布说明](pages-publication.md)。
